# 依頼: ルーティンノート(Routine Note)のアプリアイコンを作る

## あなたの役割

PWAのアプリアイコンを、**SVGで設計し、そこからPNGを書き出すところまで**やってほしい。
画像生成AIは使わない。**コード(SVG)で描く**こと。幾何学的なモチーフなので、その方が
輪郭が締まり、後から色やサイズを調整できる。

作業ディレクトリ:
`/Users/arata/Library/Mobile Documents/com~apple~CloudDocs/claude code files/app-dev/routine-debugger`
（パスに空白を含むので、コマンドでは必ず引用符を付ける）

## このアプリは何か

**パフォーマー（ジャグリング・ディアボロ・新体操・ダンス）が、音楽に合わせた演目の
「通し練習」を記録し、次に練習する場所を決めるためのノート。**

中心にある体験はこれ:
1. 技と移行を順番に並べて、曲に合わせた一本の演目を組み立てる
2. 通しで練習し、**崩れた場所をその場でタップして記録**する
3. どの技が何回崩れたかを見て、**次に練習する区間が決まる**

「高機能な分析ツール」ではなく、**練習のたびに書き足していく紙のノート**という佇まいを
大事にしている。実際、アプリ全体が**ルーズリーフ（大学ノート）**の見た目で作られている。

公開URL: https://routine-note.pygmix.com/
（実物を見て、世界観を掴んでから設計を始めること）

## デザインの前提（アプリ本体と揃える）

アプリで実際に使っている色。ここから外れないこと。

| 用途 | 色 |
|---|---|
| 紙（明るい面） | `#f8f4e9` |
| 紙の陰・罫線寄り | `#e9e3d3` |
| 表紙・外側の濃色 | `#282b27` |
| インク（文字） | `#23262c` |
| 罫線・青系 | `#39495b` |
| アクセント（朱・オレンジ） | `#a75c24` |
| 成功・良好 | `#4e7a52` |

アプリに実在するモチーフ（これらは「らしさ」の源になる）:
- **ルーズリーフの綴じ穴**（左端に並ぶ丸）と**バインダーの黒い綴じ部**
- **横罫線**が薄く走る紙面
- 技を並べた**縦のステップ列**
- 曲に対する**タイムラインの横バー**と、再生位置を示す**縦線**
- 崩れた箇所を示す**朱色の印**

## 満たすべき条件

### 技術要件（必須）

- **正方形・フルブリード**。角丸や透明背景を自分で作らない
  （iOSが自動で角丸にする。透明部分は黒く合成されて事故になる）
- 書き出す実体:
  - `icons/icon-180.png`（180×180、apple-touch-icon）
  - `icons/icon-512.png`（512×512、manifest）
  - `icons/icon-192.png`（192×192、Android向けに新規追加してよい）
  - `icons/icon-maskable-512.png`（512×512。Androidのマスク対応。**中央80%の円内に主要要素を収める**）
- SVGの原本を `icons/icon.svg` として残す（後から色や比率を直せるように）
- **アルファチャンネル無しのPNG**で書き出す
- 生成手順を `scripts/build-icons.mjs` などのスクリプトにして、再実行できるようにする
  （このMacには `~/ffmpeg-static/ffmpeg` がある。`rsvg-convert` や `sips` も検討してよい。
  新しい依存をnpmで入れるのは避け、手元にあるもので完結させること）

### 見え方の要件（必須）

- **ホーム画面の実寸（約60px）で意味が分かること。** これが最重要。
  作ったら必ず60px相当に縮小して確認し、潰れるなら要素を減らす
- **文字を入れない。** 「R」1文字も避ける。小さいと読めず、日英どちらの利用者にも中立でない
- 明るい壁紙・暗い壁紙のどちらの上でも埋もれないこと
- 他のアプリと並んだときに識別できること

### やってはいけないこと

- 汎用的な「メモアプリ」アイコン（ただの紙＋鉛筆、チェックマーク、クリップボード）
- 意味のない青紫グラデーション、発光、ガラス風、立体的なドロップシャドウ
- 何のアプリか分からない抽象図形
- **別のアプリ名に差し替えても成立してしまう見た目**

## 進め方

1. まず**方向性の異なる案を3つ**、SVGで作る。それぞれ次を1〜2行で説明すること
   - 何をモチーフにしたか
   - このアプリのどの体験を表しているか
   - 60pxで何に見えるか
2. 3案を**512pxと60pxの両方**で書き出し、並べた比較画像を作る
3. 自分で一番良いと思う案とその理由を述べる。ただし**決めるのは依頼者**なので、
   勝手に1案だけ作り込まない
4. 依頼者が選んだら、その案を仕上げて上記の全サイズを書き出す

## 選ばれた後の組み込み（4も終わってから）

1. `manifest.webmanifest` の `icons` に 192 と maskable を追加する
   （maskableには `"purpose": "maskable"` を付ける）
2. `index.html` と `sw.js` に新しいアイコンを登録する。
   **このプロジェクトはキャッシュ対策で版数を4か所そろえる決まりがある**:
   - `app.js` の `APP_VERSION`
   - `sw.js` の `CACHE` 名
   - `sw.js` の `ASSETS` 内の `?v=NN`
   - `index.html` の `?v=NN`
3. **必ず `node scripts/release-check.mjs` を通す**（版ずれや構文を検査する）
4. 変更したら、`git status --short` を目視してからコミットすること。
   ⚠️ iCloudが `icon 2.png` のような競合コピーを作ることがある。混ざっていないか確認する

## 注意

- 既存の `icons/icon-180.png` と `icons/icon-512.png` は**上書きしてよい**が、
  作業前に `icons/_old/` へ退避しておくこと
- このアプリは現在ベータ公開中で、実利用者がいる。壊れた状態でデプロイしない
- デプロイ自体は依頼者が判断する。**勝手にpushしない**

## （依頼者向けメモ・Codexには渡さなくてよい）

- Codexは画像生成AIではないので、**SVGで描かせる**のがこの指示の肝。
  幾何学的・記号的なアイコンなら、むしろコードの方が精度が出る
- 3案出させてから選ぶ形にしてあるのは、1案だけだと「無難な紙＋鉛筆」に流れやすいため
- もし写実的・絵画的なアイコンにしたい場合は、Codexではなく画像生成AIの領域になる。
  その場合は「ルーズリーフの綴じ穴」「朱色の印」といったモチーフだけ渡して別途依頼する
