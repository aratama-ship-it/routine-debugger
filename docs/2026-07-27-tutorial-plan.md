# ルーティンノート 初回チュートリアル計画書

作成日: 2026-07-27
対象: ルーティンノート ベータ版（ローカル実装 `v245` を確認）
状態: **帰宅後レビュー用のたたき台。実装は未着手**
主対象: iPhoneで初めて使うパフォーマー。iPad、Android、PCでも同じ流れを維持する。

## 1. 結論

初回チュートリアルは、機能を順番に読み上げるツアーではなく、次の一周を実際の画面で体験させる。

> サンプルの構成を見る
> → 1か所だけ編集する
> → 通し練習を1本記録する
> → 崩れた場所を分析で確認する
> → その区間をパート練習で繰り返す

中心となる理解は、次の一文。

> **ルーティンノートは、演技を通した記録から、次に練習する場所を決めるノートです。**

コア体験は **5〜7分** を目標にする。自分の音源・動画の登録、アカウント作成、完全バックアップの実行は、
チュートリアル本編では強制せず、終了後の追加ミッションへ分ける。

データ管理は、次の二段階で明示する。

1. **開始前**: 「何が端末に残り、何が外部へ送られるか」を30秒以内で理解できる短い説明
2. **終了時**: データが消える条件、任意同期、完全バックアップの場所を具体的に案内

## 2. 目的

### 主目的

- 初見の利用者が、説明を読むだけでなく、基本操作の因果関係を体験する
- 「通し記録」と「分析」と「パート練習」が別々の機能ではなく、一つの練習ループだと理解する
- 最初の操作で、自分が次に何を練習すればよいか分かる感覚を返す

### 同じくらい重要な目的

- データはまず利用者の端末内へ保存されることを伝える
- アカウントは任意であり、作らなくても使えることを伝える
- ログイン時も動画・音源・録音のファイル本体は同期されないことを伝える
- ブラウザデータの削除や端末初期化で失われる可能性と、完全バックアップの必要性を伝える
- フィードバック送信以外に、開発者が利用者の練習内容を自動閲覧することはないと伝える

## 3. 今回やらないこと

- 全機能の網羅
- 初回からA/B分岐、リスク度、版比較、動画撮影、録音を教えること
- アカウント作成の強制
- 最初から自分の音源ファイルを探させること
- カメラ・マイク権限を起動直後にまとめて要求すること
- 説明を読んだか確認するための長い同意画面
- 本人の同意なしに、チュートリアル操作ログをサーバーへ送ること

高度な機能は、基本の一周を終えた後に「次に試せること」として紹介する。

## 4. 体験設計の核

### チュートリアル名

第一候補:

**「はじめての1本」**

説明:

**「サンプルを使って、記録から次の練習を決めるところまで試します」**

「オンボーディング」「ウォークスルー」のようなサービス用語ではなく、普段の練習で使う言葉にする。

### 見た目

- 現在の生成り紙、墨、朱色、ルーズリーフの素材感をそのまま使う
- 一般的なアプリの吹き出しツアーを画面中へ重ねない
- 各画面の上部に、稽古ノートの付箋のような短い案内を1枚だけ出す
- 進捗は `SHEET 01 / 07` のように現在の世界観へ合わせる
- 1画面で求める操作は一つ
- 強調は色だけに頼らず、短い見出し、線、矢印、読み上げラベルを併用する

### 基本姿勢

- スキップ可能
- 中断しても続きから再開可能
- 完了後も「使い方」または「設定」から再実行可能
- チュートリアル中に作ったサンプルは明確に「サンプル」と表示し、後からまとめて削除可能
- 実際の個人データを勝手に変更・削除しない

## 5. 推奨フロー

### 全体

| 段階 | 体験 | 目安 |
|---|---|---:|
| 0 | アプリの役割 | 20秒 |
| 1 | データの約束 | 30〜45秒 |
| 2 | サンプルを準備 | 20〜40秒 |
| 3 | 構成を見て1か所編集 | 60〜90秒 |
| 4 | 通し練習を1本記録 | 60〜90秒 |
| 5 | 分析で崩れた場所を見る | 30〜60秒 |
| 6 | その区間をパート練習 | 30〜60秒 |
| 7 | 保存・同期・バックアップ | 45〜60秒 |
| 完了 | 自分のルーティンへ進む | 15秒 |

### 0. 役割を伝える

見出し:

**「通すたびに、次に練習する場所が決まる」**

本文案:

> ルーティンノートは、技を並べるだけのアプリではありません。
> 演技を通して、崩れた場所を残し、次の練習へつなげるノートです。

操作:

- 主ボタン: `サンプルで試す`
- 副ボタン: `あとで`
- 補助リンク: `データの保存について`

### 1. データの約束

長いプライバシーポリシーを読ませる代わりに、最初は三つに絞る。

#### この端末に保存

> ルーティン、練習記録、動画、音源、録音は、まずこの端末のブラウザ内に保存されます。

#### アカウントは任意

> アカウントを作らなくても、すべての基本機能を使えます。
> ログインするとルーティンと練習記録を端末間で同期できますが、動画・音源・録音のファイル本体はこの端末に残ります。

#### 大切な記録はバックアップ

> ブラウザのデータ削除や端末の初期化で失われる場合があります。
> 大切な記録ができたら、完全バックアップZIPを端末の外へ保存してください。

操作:

- `確認して続ける`
- `詳しく見る` → `privacy.html`

同意取得ではなく、保存方式を誤解させないための説明として扱う。

### 2. サンプルを準備する

既存の `サンプル一式を読み込む` を利用する。

見出し:

**「まず、完成したノートを触ってみます」**

本文案:

> 技、音楽、通し記録が入ったサンプルを読み込みます。
> あなたのルーティンや記録には触れません。

操作:

- `サンプルを読み込む`

完了後:

- `サンプル: はじめてのルーティン` を自動で開く
- サンプルであることと、後から削除できることを常時小さく表示する

注意:

- 初回のサンプル素材取得には通信が必要
- 取得中、止まって見えないよう進捗を表示する
- 取得失敗時は、空の画面にせず再試行と「自分で始める」を提示する

### 3. 構成を見て、1か所だけ編集する

目的:

- ルーティンが技・移行・音楽位置の並びでできていると理解する
- 編集すると構成の版が分かれることを、詳細説明なしで軽く知る

ガイド:

1. タイムライン上の指定されたサンプル技をタップ
2. 名前または順番を一度変える
3. 保存する

文言案:

> ルーティンは、演技の順番を記した一枚のシートです。
> この技を一つ動かして、保存してみましょう。

終了時:

> 構成を変えると、新しい版として残ります。前の記録と混ざらず、後から比べられます。

初回は音源トリム、動画登録、A/B分岐、リスク度へ寄り道させない。

### 4. 通し練習を1本記録する

実際の道具や広い練習場所がなくても操作を試せる「操作体験」にする。

流れ:

1. `練習する`
2. カウントダウン
3. サンプル曲を短く再生
4. 指定されたタイミングで、画面の一つの技へ `ミス記録`
5. `完走`

案内文:

> 本番のように構えたら、スタート。
> 崩れた場所だけ、その場で残します。

ミス記録の直前だけ:

> ここで一度「ミス記録」を押してみてください。

完走後:

> 記録できました。次は、この一本から何を練習するか見てみます。

この段階ではカメラ・マイクを使わず、権限要求を発生させない。

### 5. 分析を見る

目的:

- 数字を見ること自体ではなく、「次に見る場所」を決める
- 一回の記録から原因を断定しない

案内文:

> さきほど記録した場所が、分析に反映されています。
> 1本では「観察した場所」。記録が増えると、繰り返し崩れる場所が見えてきます。

操作:

- 先ほどの技の分析行をタップ

完了条件:

- 利用者が、記録した箇所と分析表示のつながりを確認する

### 6. その区間をパート練習する

目的:

- 記録を見て終わらず、次の行動へ移る

操作:

1. 対象区間を開く
2. A/B区間を確認
3. ループ再生を一度開始

案内文:

> 気になった場所だけを繰り返します。
> 記録 → 分析 → パート練習が、ルーティンノートの基本の一周です。

この時点で、チュートリアルの中心価値は達成とする。

### 7. データを守る

チュートリアル最後に、設定画面の実際の場所を見せる。

見せる項目:

- データの使用容量
- データの保護
- 完全バックアップZIP
- 任意アカウント
- 初期化

短い説明:

> 今日の記録は、この端末に保存されました。
> 大切な記録が増えたら「設定 → 完全バックアップ」からZIPを書き出してください。

ボタン:

- 主ボタン: `バックアップの場所を確認`
- 副ボタン: `あとで`
- 補助リンク: `保存と同期の詳しい説明`

サンプルだけの時点でZIP書き出しを強制しない。ベータテストの追加ミッションとして、
実際の書き出しと検証を案内する。

### 完了

見出し:

**「最初の1本を記録できました」**

本文案:

> 次は、自分の曲と技でルーティンを作ってみましょう。
> 迷ったら、ホームの「使い方」からいつでもやり直せます。

ボタン:

- `自分のルーティンを作る`
- `サンプルをもう少し見る`
- `ホームへ`

## 6. データ管理の説明仕様

チュートリアル、ベータ版ガイド、プライバシーポリシー、設定画面で表現を一致させる。

### 現在の実装で確認できた事実

| 状況 | 保存・送信される内容 |
|---|---|
| アカウントなし | ルーティン、練習記録、設定、動画、音源、録音を端末のブラウザ内へ保存 |
| アカウントあり | メールアドレス、認証情報、ルーティン・練習記録・技と音源の見出し情報をSupabaseへ保存・同期 |
| ログイン時も端末内のみ | 動画、音源、録音、通し映像のファイル本体、端末ごとの設定 |
| フィードバック送信時 | 入力本文、種類、任意の名前、アプリ版、端末・ブラウザ情報、送信日時 |
| 完全バックアップ | ルーティン、記録、設定、動画、音源、録音をZIPへ書き出す。保存先は利用者が選ぶ |
| 軽量JSON | ルーティン、記録、設定。動画・音源・録音は含まない |
| CSV | 表計算・分析用。アプリへの完全復元には使わない |
| 初期化 | この端末内のデータを削除。元に戻せないため、先に完全バックアップを案内 |

補足:

- ログイン中の同期はローカルファーストで動き、オフライン中も端末内へ保存する
- 複数端末の変更が食い違った場合、片方を黙って上書きせず両方を残す実装
- ログアウトしても、この端末の練習データは削除されない
- アカウント削除は現在、問い合わせ先への連絡で受け付ける
- GitHub Pages等の配信事業者が、接続ログを事業者側で記録する可能性はある

### チュートリアルで避ける表現

避ける:

- 「すべてのデータは端末だけに保存されます」
- 「ログインすれば全部クラウドに保存されます」
- 「データは絶対に消えません」
- 「開発者には一切情報が送られません」

推奨:

- 「データは**まずこの端末に保存**されます」
- 「ログインは任意です。ログインすると**ルーティンと記録**を同期します」
- 「**動画・音源・録音のファイル本体は同期されません**」
- 「大切な記録は**完全バックアップZIPを端末の外へ保存**してください」
- 「ご意見は、**送信ボタンを押したときだけ**開発者へ送られます」

### 情報の三層表示

#### 1. 初回の短い説明

30〜45秒で読める三項目。

#### 2. 設定内の詳細シート

端末保存、任意同期、メディア非同期、バックアップ、削除を図で示す。

```text
利用者
  ├─ この端末
  │    ルーティン / 記録 / 設定 / 動画 / 音源 / 録音
  │
  ├─ 任意の同期
  │    ルーティン / 記録 / 技と音源の見出し
  │    ※動画・音源・録音ファイルは送らない
  │
  └─ 利用者が操作したときだけ
       フィードバック送信 / ZIP書き出し
```

#### 3. プライバシーポリシー

外部サービス、保存場所、削除方法、問い合わせ先を含む正式説明。

## 7. チュートリアルのデータ設計案

### MVP

- 既存の `sampleSet`、`sampleHistory`、付属サンプル音源・技動画を再利用
- チュートリアル進捗は端末内の設定に保存
- サンプルは名前と見た目で実データと明確に区別
- サンプル削除ボタンを完了画面と技ライブラリの両方から案内
- サンプルの記録を、本人の実ルーティン分析へ混ぜない

進捗の概念案:

```text
tutorial:
  version: 1
  status: not_started | active | completed | skipped
  step: 0..7
  startedAt
  completedAt
```

端末ごとの「使い方を見た」状態なので、原則としてクラウド同期の対象にしない。

### 再開

- 中断時は次回起動で「続きから／最初から／閉じる」
- 版更新で内容が大きく変わった時だけ `tutorial.version` を上げ、必要箇所を再案内
- 小さな文言変更で毎回再表示しない

### 権限

- コアチュートリアルではカメラ・マイクを使わない
- 動画撮影、技動画、録音を初めて使う場面で、その目的を説明してから権限要求
- 拒否しても基本チュートリアルは完了できる

### 操作ログ

- 初回版では、チュートリアルの進捗を端末内にだけ保存
- 自動的なアクセス解析・行動ログ送信は追加しない
- 将来テレメトリを導入する場合は、取得項目、目的、保存期間、送信先、拒否方法を別途設計し、
  プライバシーポリシーを更新してから実装する

## 8. 既存コンテンツとの役割分担

| コンテンツ | 役割 |
|---|---|
| 初回チュートリアル | 実際に触って、基本の一周を理解する |
| 1分使い方動画 | 初見で価値を理解する。広告・紹介にも使う |
| `beta.html` 15分ミッション | ベータテスターが機能とデータ保全を広く検証する |
| アプリ内「使い方」 | 困った画面の操作を確認する |
| プライバシーポリシー | データ取り扱いの正式説明 |

同じ文章を複製しすぎず、初回チュートリアルから必要な詳細ページへ移れるようにする。

## 9. 成功条件

数値は市場一般の基準ではなく、少人数ベータで判断するための暫定目標。

### 操作

- 5〜7分程度でコアの一周を完了できる
- 説明者の助けなしで、ミス記録から分析へ移れる
- 分析を見た後、対象区間のループ再生を一度開始できる
- 自分のルーティンを作る入口を見つけられる

### 理解

テスト後、利用者が自分の言葉で次を説明できる。

1. このアプリは何のためのものか
2. 動画・音源はどこに保存されるか
3. ログインすると何が同期されるか
4. データを残すには何をすればよいか

特に次の誤解をゼロに近づける。

- ログインすれば動画もクラウドに保存される
- 開発者が練習動画を自動的に見られる
- アプリを消しても必ず元に戻る
- JSONバックアップだけで動画も復元できる

### 感情

- 「設定が多くて始められない」より「まず一回試せた」が勝つ
- 分析を試験の採点のように感じず、自分の練習ノートとして扱える
- データ説明を怖い警告ではなく、自分で管理できる安心材料として受け取れる

## 10. ベータテスト方法

### 人数

まず3〜5人。ジャグリング、ディアボロ、新体操、ダンスなど、背景が異なる人を混ぜる。

### 観察

- 最初のボタンを押すまでの迷い
- 編集画面で「何をすればよいか」が止まる場所
- 通し中にスマホまで手を伸ばせるか
- ミス記録と中止の違いが分かるか
- 分析を見て、次の行動を言えるか
- データ説明を読んだ後の理解
- チュートリアルを途中で閉じる理由

### 終了後に聞く質問

1. このアプリは何をするものだと思いましたか
2. どの画面で止まりましたか
3. 次に何を練習すればよいか決まりましたか
4. 動画と音源はどこに保存されると思いますか
5. 別端末で同じ記録を見るには何が必要だと思いますか
6. データを失わないために、何をすればよいと思いますか

正解を誘導せず、本人の言葉で答えてもらう。

## 11. QA項目

### 基本

- 新規状態で一度だけ案内される
- スキップできる
- 中断後に再開できる
- 完了後に再実行できる
- サンプルを安全に削除できる
- 実データがある利用者へサンプルを追加しても既存データを変えない

### データ

- アカウントなしで外部同期が発生しない
- ログイン時、ルーティン・記録の同期とメディア非同期が説明どおり
- ログアウト後もローカルデータが残る
- サンプルの扱いがバックアップ・復元・同期で破綻しない
- 初期化前に完全バックアップを案内
- ログイン中のZIP復元が他端末へ同期され得ることを、復元前に警告

### 端末

- iPhone Safari
- ホーム画面へ追加したPWA
- Android Chrome
- iPad
- PCのキーボード操作
- オフライン再起動
- 文字拡大、VoiceOver、色覚に依存しない表示、`prefers-reduced-motion`

### 更新

- Service Worker更新後に古いチュートリアルと新しいアプリが混在しない
- `APP_VERSION`、`sw.js`、各スクリプトの版番号をリリースチェックで確認

## 12. 実装タスク案

### TUT-01 内容確定

- 画面数と所要時間を決める
- 「操作体験」と実際の身体練習の境界を決める
- データ説明文を確定

### TUT-02 進捗管理

- 初回判定
- スキップ
- 中断・再開
- 再実行
- チュートリアル版番号

### TUT-03 サンプル導線

- 既存サンプルの再利用
